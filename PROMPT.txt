生化动力学实验室需要一个能被数据分析脚本反复调用的酶促反应速率计算端点。目标很聚焦：给定一个酶的动力学常数和底物浓度，返回该条件下的反应速率；并且在存在竞争性抑制剂时，能算出表观动力学常数如何被改变。把它做成一个长期在线的 HTTP 计算端点，而不是一次算完就退出的脚本。

无抑制时的速率遵循米氏方程 v = Vmax·[S] / ([S] + Km)，其中 Vmax 是最大反应速率、Km 是米氏常数、[S] 是底物浓度。竞争性抑制的作用是抬高表观米氏常数而不改动最大速率：v = Vmax·[S] / ([S] + Km·(1 + [I]/Ki))，此时表观 Km_app = Km·(1 + [I]/Ki)，而表观 Vmax_app 与原始 Vmax 相等。抑制类型这个字段只接受竞争性一种语义，端点不得把它悄悄当成非竞争性或混合型处理；如果调用方声明了竞争性却又传入与之矛盾的抑制因子参数，应当以带原因的错误响应挡回，而不是猜测调用意图。Lineweaver–Burk 双倒数关系可作为交叉校验的锚点：1/v 对 1/[S] 作图，纵截距 1/Vmax 在竞争性抑制下保持不变，斜率随抑制剂浓度增大而增大，端点内部无论怎样重构公式都必须让这条不变量成立。

有几组边界与非法输入必须处理干净。Vmax 不为正、Km 不为正、底物浓度为负，都属于非法输入，返回带原因的错误。底物浓度恰为零时速率为零，这是合法结果而非错误。底物浓度等于 Km 时速率恰为最大速率的一半。抑制常数 Ki 趋于极大时，抑制项 [I]/Ki 趋于零，结果应连续退回到无抑制的米氏速率，不应出现跳变或除零。这些行为要有测试逐条盯住，尤其是半饱和点和竞争性抑制下最大速率不变这两条，别在改写公式时把竞争性抑制错做成压低最大速率。

它们之间的联动关系也要经得起核对：底物浓度取到 Km 时速率必为最大速率的一半；只增大抑制剂浓度 [I]，半饱和点向高浓度一侧移动、而在极高底物浓度下速率仍逼近同一个最大速率；把 Vmax 整体放大两倍，任意底物浓度下的速率都同步放大两倍。这几条应当写进自动化测试作为回归护栏。

端点对外提供两类计算：一类只给最大速率、米氏常数与底物浓度，返回反应速率与饱和分数；另一类在此基础上追加抑制剂浓度、抑制常数与抑制类型，返回抑制条件下的速率以及表观米氏常数与表观最大速率。为方便复用不同酶的常数组合，允许把一套具名的酶动力学常数登记成参数档，请求时可点名一个已登记的酶、也可直接把常数写在请求里临时计算；服务预置一个生理浓度量级、可以手算复核的己糖激酶示范酶，用来自检速率与抑制换算是否可信。登记的酶参数档需要落地保存，端点重启后依然能按名取用；同时有多个请求并发进来时，各自的计算与酶登记各自独立、互不覆盖、结果不串。

工作范围仅限酶–底物这一层的速率与抑制换算，只以 HTTP 接口对外服务，不含任何网页界面，也不涉及登录与订单之类的外围。技术选型上，后端语言取 Python 3.12、Web 框架用 Flask；代码请合理拆分为多个模块与文件，把入参校验、米氏速率核心、竞争性抑制换算、酶参数档持久化分别放进独立模块，避免所有逻辑挤在单个文件里。交付时以容器方式打包，能构建镜像并启动容器对外提供上述接口，并附上覆盖上述不变量与非法输入的自动化测试。基础运行时锁定 Python 3.12。
